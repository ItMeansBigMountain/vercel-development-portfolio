# TikTok developer portal review packet

Use this reference when the user is inside TikTok for Developers and needs the missing app-review fields filled, not just explained.

## Deliverables to produce

- A copy/paste field packet with app name, category, description, Terms URL, Privacy URL, platform, redirect URI, scope explanation, and end-to-end flow.
- A 1024×1024 app icon PNG under the project `assets/` directory. TikTok accepts JPEG/JPG/PNG up to 5 MB; a generated PNG is safest.
- Local legal docs if public Terms/Privacy pages do not exist yet (`legal/terms.md`, `legal/privacy.md`) and/or a tiny public site route plan.
- A demo video artifact or script when the portal asks for an end-to-end integration demo. The demo should show login, profile/stat lookup, creator review, draft upload, and manual TikTok completion.

## TikTok field template

App name:

```txt
Hermes
```

Category: choose the closest available option, usually `Content Creation`, `Social Media`, or `Productivity`.

Description:

```txt
Hermes is a creator workflow tool that helps an authorized creator review, prepare, and upload short-form video clips to their own TikTok account. The app supports a manual approval flow: clips are generated and reviewed by the creator first, then uploaded to TikTok as draft/inbox content so the creator can finish editing and posting inside TikTok.
```

Terms URL / Privacy URL:

```txt
https://<public-project-domain>/terms
https://<public-project-domain>/privacy
```

Redirect URI:

```txt
https://<public-project-domain>/auth/tiktok/callback
```

Platform: `Web` unless the project has a real mobile/desktop app.

## Review explanation template

```txt
<App> uses TikTok Login and the Content Posting API to let the authorized creator upload short-form video clips generated by our workflow into their own TikTok account as draft/inbox uploads.

The app does not automatically post public videos without user review. Uploaded clips are sent to the creator's TikTok inbox/draft flow so the user can review, edit, and manually complete posting inside TikTok.

Requested scopes:
- user.info.profile: used to confirm the authorized TikTok profile and display basic profile metadata inside the workflow.
- user.info.stats: used to read creator account stats for analytics and publishing review.
- video.list: used to read the creator's existing public videos for analytics and avoiding duplicate clip concepts.
- video.upload: required for Content Posting API draft uploads so the creator can send approved clips to TikTok for final review/posting.

End-to-end flow:
1. The creator logs in with TikTok and authorizes <App>.
2. <App> displays the authorized creator profile and account stats.
3. The creator reviews candidate short-form clips in <App>.
4. The creator approves a selected clip for TikTok.
5. <App> uploads the approved MP4 through the Content Posting API draft/inbox upload endpoint.
6. The creator receives the TikTok inbox/draft notification and completes final editing/posting in the TikTok app.
```

## App icon fallback

If managed image generation is unavailable, do not stop. Create a simple PNG programmatically using Python stdlib or any installed image tooling. Validate the PNG signature, dimensions, and size. For developer portals, a polished abstract mark is enough for review; avoid text in the icon.

Suggested icon brief: dark rounded-square gradient, cyan/magenta accents, abstract messenger/radar/play motif, no text, centered symbol, 1024×1024.

## Pitfalls

- TikTok review URLs must be publicly reachable. Local markdown files are useful drafts but not enough for final review.
- Do not claim Direct Post if the app only has draft upload. Phrase everything as creator-reviewed draft/inbox upload unless `video.publish` and Direct Post are approved.
- The user often wants ready-to-paste values and files immediately; provide concrete artifacts first, then short warnings/next steps.
