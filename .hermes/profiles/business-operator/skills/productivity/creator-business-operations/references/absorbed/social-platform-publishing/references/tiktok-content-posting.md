# TikTok Content Posting API — developer portal/session notes

Captured from a TikTok Developer Portal troubleshooting session for a clipping/publishing workflow.

## Observed portal state

The developer app showed these scopes available:

- `user.info.stats` — read a user's statistical data such as likes count, follower count, following count, and video count.
- `user.info.profile` — read additional profile information such as profile links, bio description, and verification status.
- `video.list` — read a user's public videos on TikTok.

These are read-only for the publishing workflow. They are useful for analytics/profile confirmation but cannot upload clips.

The Products page showed **Content Posting API** added. **Direct Post** was toggled off. That should not block a draft/inbox pilot.

## Scope distinction

TikTok Content Posting has two upload/publishing paths:

### Draft/inbox upload

- Required scope: `video.upload`
- Endpoint: `https://open.tiktokapis.com/v2/post/publish/inbox/video/init/`
- User experience: TikTok sends the upload to the creator's inbox/draft flow. The creator reviews/edits/completes posting inside TikTok.
- Best first pilot because it keeps user review in the loop and is usually easier than direct post.

### Direct post

- Required scope: `video.publish`
- Endpoint: `https://open.tiktokapis.com/v2/post/publish/video/init/`
- User experience: content is posted directly to the authorized profile according to the API request metadata.
- Harder approval; requires direct-post access/approval. Do not make this the first blocker if draft upload is acceptable.

## Upload mechanics

For local file upload (`FILE_UPLOAD`):

1. POST JSON to the relevant init endpoint with bearer token.
2. Include `source_info` with:
   - `source: FILE_UPLOAD`
   - `video_size`
   - `chunk_size`
   - `total_chunk_count`
3. TikTok returns `publish_id` and `upload_url`.
4. PUT the MP4 bytes to `upload_url` using:
   - `Content-Type: video/mp4`
   - `Content-Range: bytes <start>-<end>/<total>`
5. Check status with `/v2/post/publish/status/fetch/` using the `publish_id`.

For URL upload (`PULL_FROM_URL`), the video URL must be public/acceptable to TikTok. Direct file upload avoids public hosting during early pilots.

## Review-form guidance

If the app review form asks how products/scopes work, use language like:

```txt
Hermes uses TikTok Login and the Content Posting API to let the authorized creator upload short-form video clips generated by our workflow into their own TikTok account as draft/inbox uploads.

The app does not automatically post public videos without user review. Uploaded clips are sent to the creator's TikTok inbox/draft flow so the user can review, edit, and manually complete posting inside TikTok.

Requested scopes:
- user.info.profile: used to confirm the authorized TikTok profile and display basic profile metadata inside the workflow.
- user.info.stats: used to read creator account stats for analytics and publishing review.
- video.list: used to read the creator's existing public videos for analytics and avoiding duplicate clip concepts.
- video.upload: required for Content Posting API draft uploads so the creator can send approved clips to TikTok for final review/posting.
```

## Implementation lesson

A helper script should expose a `--mode draft|direct` switch and default to `draft`. Dry-run output should include:

- mode
- endpoint
- required scope
- redacted credential/token requirement
- payload

This prevents accidentally building a `video.publish`/direct-post flow when the app only needs or only has draft upload access.
